# ESP32 原生 macOS 接入

## 路径与兼容范围

ESP32 原生 USB 插在被控电脑上，Mac 通过 WebSocket 向 ESP32 发送协议 2 / NKRO16 输入。无需重刷兼容的旧固件。

鼠标移动、滚轮、CoreHID 后端及视频显示保持上游实现。首版接管物理键盘和物理鼠标五键；手柄模拟点击不纳入 ESP32 接管。

应用名称为 `MoonlightESP32.app`，标识为 `org.worldline233.MoonlightMacESP32`。与原增强版分开保存配对、设置及权限，需要在新应用里重新配对和授予所需权限。

## 配置和使用

1. 退出旧 Qt 客户端串流、独立 Bridge 和 ESP32 控制网页，释放控制权。
2. 在本应用配对串流主机。打开设置，选择具体主机配置。
3. 在「键盘与鼠标 → ESP32 USB 输入」填写设备地址、端口（固件默认 80）和 6 位数字控制密钥。
4. 选择键盘和鼠标按钮。仅在本地使用的按键填入排除名单，采用 `MetaLeft,MetaRight,KeyQ` 等固件名称。
5. 保存并重新开始串流。配置按主机 UUID 隔离，不从全局配置继承设备地址。
6. 捕获输入时，`Control+Option+Shift+F9` 暂停/恢复 USB 输入，`F10` 重连 ESP32，`F11` 释放全部 USB 输入。若键盘将功能键设为媒体键，需要同时使用 Fn。

键盘开启后走独占 USB 路径：断线、暂停、固件不兼容或配置无效时均不绕回 Sunshine。键盘使用物理键位，左右修饰键独立；固件不支持的键会被消费。键盘翻译、按字符映射、Mac 输入法文本和剪贴板键入在独占模式不可用。本地退出、解除捕获等串流快捷键保留。

鼠标按钮按一次按下到抬起的完整过程固定路由。连接正常时选定按钮通过 ESP32；未选按钮仍走 Moonlight。离线的新点击可走 Moonlight；USB 暂停时选定按钮被阻止。恢复连接不重放旧的按住状态，需松开重按。

结束串流、连接终止、失败退出或重新创建串流会话前，会主动停止旧 ESP32 连接，不等待窗口或输入对象销毁，避免固件的单控制连接被旧会话占用。切出窗口仅释放输入，保留当前连接。

失焦、解除捕获和退出会释放输入。原生按钮按下、抬起与强制释放共用输入队列；取消时丢弃未发送的旧按下，保留正常抬起及强制释放，重新按下属于新的输入批次。备用鼠标驱动回调与失焦处理使用同一把路由锁。替换或清除输入上下文前会排空已提交的输入任务。通信使用单独的串行队列和有界待发队列；重连、释放、暂停后的旧报告不得重新出现。网络失联时最终释放仍依赖固件约三秒看门狗。

控制密钥保存在此应用的本机偏好设置中，不加入项目；日志只记录连接状态，不记录设备 URL 或密钥。开发包停用上游自动更新，避免 ESP32 包被原增强版更新覆盖。

## 真机验收

- 先关闭 ESP32，与同版本原增强版使用相同主机、鼠标模式、渲染器和帧率，对比手感。
- 启用 ESP32 后，再比较鼠标移动；验证键盘和选定按钮只有一次输入，未选按钮及滚轮正常。
- 左右 Shift/Ctrl/Option/Command、组合键、长按、快速连点、同时 16 键。
- 按住键或按钮后切出、解除捕获、暂停、退出；主机不得持续保持按下。
- 拔网或停止 ESP32，再恢复；键盘不得走 Sunshine，旧按键不得自动重放，松开重按后恢复。
- 连续三次结束串流后立即重连，确认每次键盘和鼠标按钮都恢复；再测试连接失败后的重试。
- 切换到未配置的另一台串流主机，确认不会连接或控制之前的 ESP32。

2026-11-05，[源码 `baf381a` 的 Mac ARM64 Action](https://github.com/worldline233/Moonlight_macOS_ESP32/actions/runs/42012464637) 已通过原生按钮队列回归、配置、WebSocket 模拟联机和保留旧会话的连续退出重连测试、完整应用编译、开发签名校验及打包上传。以上硬件真机验收仍待完成；云端测试不证明端到端延迟，也不替代固件联调。

本次只修复原生按钮释放顺序。Free Mouse 下移动与 ESP32 按钮仍分通道，尚未解决跨通道点击与坐标的严格同步；现有 USB 按钮功能保留。

## 独立 ESP32 状态条

开启 ESP32 后默认在顶部居中显示一行紧凑状态条：连接/暂停状态、键盘与鼠标按钮通道。未捕获输入时另有提示；固定使用英文，不随界面语言切换，不显示延迟等性能数据。

在具体主机的「键盘与鼠标 → ESP32 USB 输入」中切换「显示独立 ESP32 状态条」，立即生效，无需重新串流。该显示开关独立于原性能监控；两者同时开启时 ESP32 条放在性能条下方。状态条不拦截鼠标点击，退出时停止刷新并移除。

状态条在视频视图就位、串流建立后创建，避免被视频遮挡；视频视图替换后刷新会恢复层级。Mac Action 的 `python3 tests/esp32/status_bar.py` 使用实际生产 AppKit 方法验证独立显示、层级恢复、双条堆叠、开关和清理。


## 可设置按键的抢占宏

在具体主机的 ESP32 设置中选择 可设置按键的抢占宏功能键（默认关闭）。串流捕获期间用
Control+Option+Shift 加所选键触发；F9/F10/F11 保留暂停、重连、释放用途。
重复次数默认 3，可选 3–5；按住和松开间隔默认各 2 ms，可调整。
如果功能键作为媒体键使用，需要同时按 Fn。保存后重新串流生效。

需要握手支持 `exclusive_latest_state` 的新固件。旧固件仍可正常传普通键鼠，触发宏时提示升级。
Mac 继续按变化发送完整键盘和按钮状态；ESP 期间只记录，不输出普通 HID。
宏结束由 ESP 直接恢复最新状态（方案 B），期间完整发生的短按和短点击不补发。
鼠标移动与滚轮仍使用上游原生路径，未接管按钮不受 ESP 独占控制。
暂停、释放全部、解除捕获和退出会取消宏并清空状态，不恢复旧按住状态。

## Mac 原生 USB 升级工具

云端包附带 `USB-Upgrade/`。将应用固件 `lan_usb_keyboard.bin` 和对应的 `sha256.json`
放在该目录，双击 `esp32-usb-update.command`。工具在 USB 实际连接的 Mac 上运行，
使用系统 IOKit 的独立厂商 Feature 接口，不安装 HID 驱动，不占用键盘和鼠标接口。
升级时停止输入，进入 ROM 下载模式，核对芯片 MAC 和分区后只更新应用，保留 Wi-Fi 配置。

首次使用按启动器提示创建 `.venv` 并安装 `esptool>=5.6,<6`。源码目录可用
`python3 scripts/esp32-usb-update.py <应用固件.bin>`，会用 Xcode Swift 执行 IOKit helper。
发布包带已编译 ARM64 helper，无需为了运行 helper 安装 Xcode。
`--list` 只读列出支持设备，`--mac` 选择设备；中断后可用 `--port /dev/cu.usbmodem... --mac ...` 继续。
USB 升级依赖支持此功能的固件；本项目不改变 ESP 固件的 USB 升级协议。

宏输出按键与触发快捷键分别设置，默认输出 E。输出可填 E、F、1、F1、Space、Enter 等单个普通键（不含组合键）；下次串流生效。需要支持 `exclusive_configurable_key` 的新版 ESP 固件，旧固件不会执行此命令。
已接入提供的左下角图标数字 5 检测。在 ESP32 设置中打开自动执行宏，保存并重新串流。默认关闭；连续两次确认 5 后执行一次宏，保持 5 不重复，连续三次确认数量为 0～4 后重新待命；目标保持为 5 时换槽位不重复触发。

数字识别使用解码源画面，与客户端窗口大小无关。720p–8K 的 16:9 缩放模拟已检查；原生不同 UI 比例或图标位置仍需实测。Windows 后台显卡读回仅保留一帧，Mac 后台读取亮度区域；暂停、失焦、断线时不执行自动宏。新样本已补齐无数字的 1、×2、×4；HDR 和不同布局仍需实测。

## Mac 诊断版：不使用快捷键测试

设置中的宏输出统一显示 `E`，`KeyE` 仅为协议内部的同一个 E 键编码。
在串流窗口菜单中点击“测试 ESP32 宏（3 秒后执行）”，回到串流画面，3 秒后使用当前配置执行一次宏。
焦点或捕获未恢复、串流已切换时取消测试，并记录具体原因；不会绕过暂停或断线门控。
“记录 ESP32 诊断信息”可写入即时快照。

应用日志查看器搜索 `ESP32`，可见 config、connection、handshake、video-path、frame、vision-gate、recognition、vision-trigger、macro、device-status。
识别日志包含视频格式、尺寸和 ROI、图标/数字分数、阈值、连续确认与锁定状态；每秒汇总，状态改变或触发时即时记录。
无解码帧时看门狗会明确提示检查渲染路径；不支持的格式、无亮度平面、锁定失败、比例不符和过期帧分别记录。
宏记录请求编号、排队、发送和发送失败；`transport_sent` 只表示网络发送完成，不等于 USB 已执行。
`device-status` 是 ESP 返回的执行状态快照；当前协议没有 USB 完成确认，日志不会将其显示为已确认输出。
日志不写控制密钥、连接 URL 或普通用户按键内容。可在应用日志查看器导出；原始日志路径为 `~/Library/Logs/MoonlightESP32/`。

## 三个槽位与数量 0～5

目标图标不存在为 0，无数量数字为 1，×2～×5 为对应数量。先匹配目标本体，再比较 1～5 的数量模板；紫色 5、灰色 3 等其他图标不触发。
旧视频位置为最右槽，向左延伸两个等距槽位（2560×1440 基准从左到右的本体坐标为 702,1226 / 760,1226 / 818,1226；间距 58）。间距从新裁剪图的 65 像素按 1.125 倍反算，整排绝对位置沿用旧视频；新全屏布局待实机确认。
连续两次为 5 触发一次。保持为 5 或在槽位间移动不重复；连续三次确认 0～4 后重新待命。识别不清和不支持的帧不解锁。
原生测试验证三个位置的 0～5，以及实际解码触发一次后经过未知格式和移位仍只发送一次宏。额外的用户素材合成测试覆盖十二种分辨率、轻微偏移、亮度映射和 JPEG；它们不等于不同分辨率的原生 UI 实测。

两端最小采样间隔现为 10 ms；仅在有新视频帧且识别后台空闲时处理，忙时跳过，不积压。实际频率取决于帧到达节拍和处理耗时，并非固定 100 Hz。两次确认、防重复和宏按键时序保持不变。

## 数字对齐修复、识别参数与性能

新原视频证实：图标本体槽位坐标正确，但左/中槽位的数字比旧固定取框向右偏 1 像素。数字 5 的相关分数从约 0.65 恢复到约 0.99；现在在数字周围 ±1 像素对齐，未降低阈值。
主机 ESP32 设置新增连续确认次数（1～2，默认 2）与最小采样间隔（1～1000 ms，默认 10）。保存并重新串流生效。长采样间隔对应的确认间断容忍同步调整；连续三次确认 0～4 才重新待命的规则不变。
vision-performance 记录后台排队、转换、取区、匹配、样本总年龄、配置及数字偏移；macro-performance 记录网络队列等待与发送完成耗时。网络发送完成不证明 USB 已执行，也不等于从远程画面变化到按键的端到端延迟。

## 识别状态生命周期修复

暂停、释放全部或失去输入捕获时，统一中断尚未完成的确认计数，保留已触发五层的防重复锁定。过期后台任务不能再修改当前识别状态，避免暂停恢复是否重复触发取决于任务时序。原生回归通过串行队列屏障强制制造过期任务，并比较有/无执行中任务的两种情况；云端构建仍需验证。

按用户要求，自动识别不额外要求窗口焦点。Mac 原有 observer 路径只向识别桥传入输入捕获状态，桥内不另行检查窗口焦点；该行为保持。Windows 已取消额外 focus 条件。输入捕获、暂停、连接、代次与过期检查仍然生效，原生鼠标/普通输入的捕获策略不改动。
